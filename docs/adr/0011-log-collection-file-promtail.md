# ADR 0011: Логи — JSON в файл, дальше Promtail

- **Дата:** 2026-07-20 · **Статус:** Accepted

## Задача

Шаг 7.3 собирает логи в Loki. Сервисы уже пишут структурный JSON. Вопрос — как он туда
попадает, и мешает асимметрия окружения: часть сервисов запускается на хосте и пишет в
консоль, product-service работает в контейнере. Promtail в контейнере вывод хостовых
процессов не видит.

## Что решили

Сервисы пишут JSON **в общий каталог `logs/`**, Promtail монтирует его только на чтение,
тейлит файлы, разбирает JSON в метки `service` и `level` и отправляет в Loki.

Так один и тот же конвейер работает и для хостовых процессов, и для контейнеров, и ближе
всего к тому, что будет в Kubernetes, где коллектор тейлит вывод подов.

## Почему не иначе

- **Отправлять логи прямо в Loki из приложения** (loki4j-appender) — тогда Promtail не нужен,
  но приложение начинает знать про бэкенд логов, и смена его потребует правки кода.
- **Тейлить только docker-логи** — покрывает один сервис из семи.

## Чем платим

- Logback пишет дважды: в консоль для человека и в файл для Promtail.
- Появляется зависимость от рабочего каталога: сервис должен запускаться из корня проекта
  либо получать `LOGS_DIR`.
- **Известный долг:** в Kubernetes писать в файл внутри пода неправильно — логи умирают
  вместе с ним. Там принято писать в stdout; наш выбор сделан под docker-compose.
