# ADR 0015: Один параметризуемый чарт вместо семи почти одинаковых

- **Дата:** 2026-07-28 · **Статус:** Accepted

## Задача

Шаг 9.1 требует Helm-чарт «для одного сервиса». Формулировка допускает два прочтения: заготовка
под любой сервис или конкретный чарт product-service. У нас семь сервисов с почти одинаковыми
манифестами — различаются образ, порт, набор переменных и пара мелочей вроде gRPC-порта.

## Что решили

Один generic-чарт `helm/microservice`, который umbrella-чарт подключает семь раз с разными
значениями.

Приёмы, которые оказались важны:

**Метки для селектора — минимальные и стабильные** (`name` + `instance`, без версии). Селектор
Deployment в Kubernetes **неизменяем**, а версия меняется при каждой выкатке — попади она в
селектор, обновление стало бы невозможным. Один хелпер задаёт метки сразу для трёх мест:
селектора Deployment, меток пода и селектора Service.

**Число реплик имеет ровно одного хозяина.** При включённом автомасштабировании чарт не пишет
`replicas` вовсе, при выключенном — не рендерит HPA. Иначе Helm и HPA перетягивали бы число
подов друг у друга.

**ConfigMap подключается целиком** через `envFrom`, а его имя получает суффикс, чтобы не занять
DNS-имя сервиса. Порт назван, и пробы ссылаются на имя, а не на число.

**Контрольная сумма конфига в аннотации пода:** переменные читаются только при старте, поэтому
без этого приёма `helm upgrade` менял бы ConfigMap, а поды продолжали работать со старыми
значениями.

## Почему не иначе

Отдельный чарт на сервис проще написать здесь и сейчас, но дальше это семь почти идентичных
копий: правку пробы или метки надо повторить семь раз, и рано или поздно они разойдутся.

## Чем платим

- Чарт обязан покрывать различия сервисов **значениями**, а не переписыванием: gRPC-порт,
  отсутствие HTTP-сервера у чисто-событийного notification-service.
- Секреты в чарт не входят — только несекретный ConfigMap; ключи и сертификаты появятся
  отдельным шагом.
- Автомасштабирование требует metrics-server, которого в k3d нет по умолчанию: манифест
  валиден, но проверить живьём можно только на поднятом кластере.
