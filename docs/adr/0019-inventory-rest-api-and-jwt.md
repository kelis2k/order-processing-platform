# ADR 0019: REST-API остатков и JWT в inventory

- **Дата:** 2026-07-30 · **Статус:** Accepted

> **Обновление (ADR 0022, 2026-08-02):** gRPC-метод `Release` удалён, списание резерва при отгрузке
> идёт событием. Маршрут `/inventory/**` в шлюзе появился только на шаге 10.1.D — до этого REST-API
> остатков снаружи был недостижим.

## Задача

У inventory-service не было способа завести остаток. gRPC-методы обслуживают резервирование, но
не поступление товара, а миграция таблицу не наполняет. Во всех прогонах остаток заводился прямым
`INSERT` в чужую базу.

На шаге 5.5 сервис сознательно оставили без JWT: снаружи он не торчал, внутрь ходили только по
gRPC, закрытому mTLS. Проверка показала, что **Spring Security в нём отсутствует вовсе** — порт
8084 отдавал только actuator.

Появление REST-эндпоинта меняет расклад: у операции «изменить остаток» возникает вопрос «кому
можно», которого раньше не было.

## Что решили

**`PUT /inventory/{productId}` с абсолютным значением**, под `ROLE_ADMIN`. Плюс `GET` для просмотра.

Абсолютное значение, а не дельта: такой вызов **идемпотентен** — повтор ничего не меняет. Вариант
«прибавить партию» ближе к складской реальности, но повторный вызов удваивает остаток, и демо
становится чувствительным к повторам.

**Защита — JWT resource-server**, как у остальных сервисов. Вариант «не маршрутизировать REST через
шлюз и понадеяться на недоступность порта» отвергнут: это security by obscurity, любой под в том же
namespace обнулил бы склад.

Резервирование по-прежнему идёт **только по gRPC под mTLS**. JWT — второй, независимый механизм для
внешних REST-операций.

**Существование товара в каталоге не проверяем.** Технически теперь могли бы, но это добавило бы
связность в рантайме, а на складе партия вполне может появиться раньше карточки в каталоге — такой
порядок мы бы запретили.

## Чем платим

- У сервиса стало **два** механизма безопасности вместо одного — модель сложнее, но иначе REST
  остаётся открытым нараспашку.
- Появилась зависимость от auth-service при старте REST-части.
- В Kubernetes сервис остаётся внутренним: снаружи кластера остатки не изменить, только через
  port-forward или шлюз.

Попутно у inventory впервые появились Swagger и обработчик ошибок — сервис перестал быть слепым
пятном в документации.
